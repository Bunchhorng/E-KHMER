# F18 — Broken Barcode Browser Assertion

---

# 1. CURRENT DEFECT

The full desktop/mobile browser suite currently has a failing barcode assertion.

The audit found the failure around:

```text
frontend/tests/e2e/commerce.spec.ts:371
```

The actual selected variant appears to scan correctly.

The failure is caused by a stale/ambiguous selector.

Current test logic uses something equivalent to:

```ts
locator(...).last()
```

The DOM now contains more than one relevant barcode field.

As a result:

```text
.last()
```

selects the scanned second variant barcode field instead of the independent top-level product barcode field that the assertion intended to verify.
